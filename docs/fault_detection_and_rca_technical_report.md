# 故障检测与根因推理技术设计

## 1. 目标与范围

本流程以日志、指标、NetFlow 五元组和 Traffic Flow 四类检测器产生的异常事件为输入，识别故障发生区间，并在区间结束后推断故障类型与根因网元。最终输出符合赛事格式的 `predictions.jsonl` 提交文件。异常事件表示观测到的症状，故障结论由跨源证据关联和状态机决策形成。

整体流程为：**四类异常事件 → 事件规范化与质量评估 → 故障语义先验 → 逐分钟故障状态机 → 事后根因推理 → 时间先验后处理 → 标准提交文件**。所有时间统一为 UTC；故障类型和网元标识遵循仓库中的官方配置。状态机负责故障发现、证据归属和区间切分，故障类型与根因在区间结束后确定。时间先验后处理基于已生成结果单独运行，保留原始提交文件。

## 2. 输入事件

四类检测器均以 `evidence_events.jsonl` 提供异常区间。每条事件包含证据标识、起止观测分钟、观测网元、数据模态、异常特征、变化方向与来源属性。状态机按事件实际覆盖的分钟处理，持续事件保留同一证据身份，避免重复计为独立异常。

统一事件采用 `start_minute` 和 `last_seen_minute` 表示**实际观测到异常的首末分钟**，两端均包含在事件内；单分钟异常满足两字段相等。指标检测器当前逐异常采样点输出单分钟事件；日志先按模板、实体等属性聚合到分钟，再将相邻异常分钟合并为事件，因此既有单分钟事件也有连续事件；NetFlow 五元组和 Traffic Flow 按各自检测条件输出异常区间。统一的是字段和时间语义，不要求四类检测器采用相同的合并粒度。日志的 `log_events_anomaly_templates.csv` 是逐分钟审阅文件，跨模态接入以合并后的 `evidence_events.jsonl` 为准。只有同一检测对象、同一特征与方向、且相邻分钟均有异常证据时，才可在下游合并；不能仅因同一实体的事件在时间上接近，就补齐没有观测证据的分钟。逐分钟展开区间时，同一 `episode_id` 仍只代表一份持续证据，不因持续分钟数增加而成为多份独立证据；指标的连续单点事件当前具有不同 `episode_id`，下游评估独立证据数时还需按原始指标及异常类型识别同源持续性。此处的闭区间与最终 `predictions.jsonl` 使用的半开故障区间分别处理。

| 数据来源 | 主要异常事件 | 在故障推理中的作用 |
| --- | --- | --- |
| 日志 | 路由协议报错、邻居状态变化和异常消息聚集 | 提供控制面变化及其发生顺序 |
| 指标 | 资源压力、接口质量、路由状态及预期指标值缺失 | 提供网元状态、资源变化与观测缺失证据 |
| NetFlow 五元组 | 接口或流组流量变化、方向失衡、控制流变化 | 提供转发侧症状和观测位置线索 |
| Traffic Flow | 主动探测错误、超时、时延和传输质量异常 | 提供业务影响及源、目标区域线索 |

事件仅使用有来源依据的字段和实体。检测器判定“按历史采样规律或采集约定本应有值、实际却缺失”时，`missing_value` 是异常事件，可以参与故障启动、关联和强度计算。单纯无事件、未采集或覆盖未知不等同于这种缺失值异常，也不能自动表示正常或故障。

## 3. 处理模块

### 3.1 事件接入与规范化

**工作内容：**读取四类异常事件，校验时间、网元、模态和事件标识；将特征映射到统一事件名称与事件族，并保留原始来源、观测区间和实体属性。

**关键技术：**统一 UTC 分钟时间轴、事件语义映射、稳定证据标识和来源追踪。缺失值事件中的“当前无有效数值”不妨碍其作为检测器确认的异常事件进入推理。不同模态的原始异常分数保留各自语义，不直接跨源相加。

### 3.2 证据质量与依赖处理

**工作内容：**结合异常强度、可靠度、观测覆盖及变化新颖性评估证据质量；识别同一采集源或同一底层变化派生的相关事件，限制重复贡献。对缺失值事件核实预期采样依据和采集健康状态，区分可归因的异常缺失与覆盖未知。

**关键技术：**按特征标定分数、依赖组封顶、持续证据衰减、预期值缺失判定和观测有效性控制。可信的缺失值事件可支持同一故障；采集源整体失效时降低其诊断权重，不能把所有缺失列重复计为独立证据。质量分数用于相对决策，不解释为故障概率。

### 3.3 故障语义先验与证据关联

**工作内容：**预先建立异常事件的故障指示权重、事件间的条件关联权重，以及故障类型与事件的支持关系。大模型依据事件类型、官方故障类型和可核实的网元关系提出这些语义权重，经规则校验后作为状态机与事后推理的先验。缺失值事件也参与事件间和故障类型间的关联判断。在线处理时，以时间、实体、方向和事件类型判断新证据与当前故障历史证据是否关联。

**关键技术：**有限时间窗内的条件关联、依赖来源去重、类型相关的证据权重和实际拓扑约束。先验未列出的事件关系视为未知，由同一时间段的证据强度、实体关系和后续持续性共同判断；不能直接判为无关联。在线评分可参考故障类型先验，但不将候选类型提前固定为最终诊断。

当前无标签校准将可信缺失值归为弱证据：事件显著度为 `0.38`，同实体缺失与其他异常的条件关联权重为 `0.72`；对应采集器同期不健康时，缺失证据质量折半。同一实体、同一采集源的多列缺失先合并，避免按列数放大强度。单个缺失事件可提供维持支持，但不足以达到同故障延续阈值。这些数值是可回放的启发式权重，不是故障概率；缺失本身不指定故障子类。

### 3.4 故障推理状态机

**工作内容：**按分钟维护全局 `NORMAL`（非故障态）和 `FAULT`（故障态）以及当前故障的异常事件列表。每分钟处理全部有效异常证据，并在完成证据归属和强度计算后作一次状态决定。

| 当前状态 | 每分钟处理与状态决定 |
| --- | --- |
| `NORMAL` | 监控本分钟观测，评估异常事件是否构成潜在故障。达到启动条件时，暂存可能导致故障的事件并进入 `FAULT`；否则保持监控。 |
| `FAULT`：关联证据 | 将本分钟每条异常证据（包括可信缺失值事件）与已暂存事件比较。可能属于同一故障的证据加入事件列表，并计算这些证据对当前故障的支持强度。 |
| `FAULT`：未关联证据 | 评估其是否构成新的潜在故障；达到启动条件时形成新故障候选，并计算其强度。先验未覆盖的关系继续结合观测证据判断。 |
| `FAULT`：故障消退 | 当当前故障的支持强度低于维持条件、没有已确认的新故障，且低强度持续超过 `gap` 时间时，结束故障区间并回到 `NORMAL`。覆盖未知不直接视为故障消退。 |

**同一分钟两组证据并存时**，先用已关联的证据计算当前故障强度，再用尚未关联的证据计算新候选强度。两侧采用相同的质量与依赖约束；归属未定的证据暂存，不在两侧重复计分。当前故障的强度必须在接纳新证据**之前**计算，以免新证据反过来影响本分钟的归属决定。随后按以下顺序处理：

1. 新证据不足以启动故障时，未归属证据留在短期候选窗口；当前故障是否维持，继续由其支持强度和 `gap` 决定。
2. 新候选达到启动条件，且当前故障强度达到**同故障延续阈值**时，保持 `FAULT`，将新证据归入当前故障。即使新候选强度更高，也不据此切换；这种并存说明原有事件关联先验可能遗漏了同一故障的症状关系。
3. 当前故障强度低于同故障延续阈值时，才比较两侧强度与持续性。新候选已形成更有力的故障过程时切换；其余情况保持当前故障，并暂存新候选供后续分钟复核。新故障分数高于旧故障**本身不是**充分的切换条件。
4. 当前故障持续低于维持条件、又没有可启动的新候选时，超过 `gap` 后回到 `NORMAL`。若新候选已确认且满足第 3 步的切换条件，不等待原故障的恢复 `gap`。

同故障延续阈值高于最低维持阈值，用来识别旧故障仍有充分有效支持的分钟。当前无标签回放采用同故障延续阈值 `0.25`、最低维持阈值 `0.18` 和新候选强度优势 `0.12`；三者均为相对支持分数，后续应随案例审阅调整。切换时保留两侧证据的归属，边界分钟的证据不重复计入两个故障。先验没有列出某对事件的关联，只表示关系未知，不能单凭先验缺项宣布出现第二次故障。

**关键技术：**潜在故障启动、逐证据关联与归属、当前故障和新故障的强度比较、`gap` 控制及非重叠区间切分。当前故障获得持续支持时更新其最后有效支持时间；确认切换时先关闭原故障，再以新故障的相关证据建立新区间。故障起点可回溯到首个有效关联事件，结束时间以最后有效支持和 `gap` 决策确定，恢复等待不自动延长提交区间。

### 3.5 事后根因推理

**工作内容：**故障区间关闭后，汇总该区间接纳的证据，联合评估故障类型和可能的根因网元。推理区分直接状态证据与受影响业务症状，并根据实际观测的实体关系和拓扑约束排序候选。

**关键技术：**故障类型与事件族先验、同源证据去重、故障类型与网元联合排序。证据不足时不凭区域相邻或流量经过某路由器推定具体根因；只有满足提交条件的故障区间进入最终结果。

### 3.6 故障长度裁剪

**工作内容：**对状态机结果中超过 30 分钟的故障按直接证据或影响证据裁剪。若高强度证据集中在不超过 30 分钟的片段，保留该片段及少量上下文；否则选择证据最强的连续 30 分钟。BGP 会话掉线优先使用 `bgp_peer_up=0` 定位掉线区间，不把会话恢复后仍偏低的 uptime 异常当作持续掉线。

**关键技术：**逐分钟证据强度和最强连续窗口选择。后处理保留原始故障数量、类别和根因，只改动超长故障的起止时间；不合并、切分、补报或按故障间隔筛选。原始结果作为只读输入，后处理生成独立的 `predictions.jsonl`。

## 4. 标准提交文件

输出文件为 JSONL 格式的 `predictions.jsonl`，每行对应一个故障区间，严格包含以下字段：

| 字段 | 含义 |
| --- | --- |
| `prediction_id` | 唯一故障预测标识 |
| `start_time`、`end_time` | UTC 故障区间；结束时间为半开区间右端点 |
| `root_cause_top5` | 最多五个合法网元，按 `rank` 从 1 开始排序 |
| `fault_category` | 官方 `major_category` 与 `sub_category` 组合 |

写入前校验时间顺序、预测标识、根因网元及故障类别，并确保正式故障区间不重叠。提交字段以 [预测格式校验器](../aiops_challenge_2026/schema.py) 和 [官方故障类型配置](../aiops_challenge_2026/config/fault_taxonomy.json) 为准。
